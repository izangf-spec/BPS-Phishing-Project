# Phishing Threat Intelligence Dashboard

Business Process Support project: a management dashboard concept for URL-based phishing and abuse threat intelligence, built on PhishVN v4 (open archive `PhishVN_v3.1.0_open.zip`). The publisher states that the v4 data files are byte-identical to v3.1.0.

## Status of the second deliverable (13 Nov 2026)

- **Model notebook:** `project/project-model.ipynb`, sections 0 to 13, run from top to bottom (about 5 minutes, 0 errors) with its outputs saved.
- **Saved model:** `project/model.joblib` (logistic regression with the top-level domain, isotonic calibration, threshold 0.22). It is reloaded and checked by `project/test_saved_model.py` in a separate process.
- **Audit:** `INFORME_AUDITORIA_ENTREGA2.md` lists every requirement of the official brief with its status (CUMPLE / NO CUMPLE / NO VERIFICABLE) and the evidence for each.
- **Open limits:** the test set is not clean (it was read in an earlier version and no independent sample exists), there is no documented current rule to compare against, and the official template, the GitHub link and the deadline depend on the user.

## Reproduce the model

From `project/`, with Python 3.13 and `pip install -r requirements.txt`:

1. Run the notebook from top to bottom (`Restart and run all`, or the `jupyter nbconvert --execute` command in `project/README.md`).
2. Run `python test_saved_model.py`. Exit code 0 means all 21 checks passed.

## Run checks on Windows

From the repository root, with Python 3.10 or later:

```bat
py scripts\profile_dataset.py
py scripts\quality_checks.py
py scripts\inspect_duplicates.py
py scripts\validate_project.py
```

The scripts use the Python standard library, do not modify the original CSV and never visit URL values. Host-level URL collisions are review flags, not permission to delete rows automatically. Validation checks package structure and selected brief requirements; it cannot guarantee a grade or replace the instructor's qualitative assessment.
